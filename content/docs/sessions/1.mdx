## 개념

### 바이브 코딩의 탄생

2025년 2월 2일, OpenAI 공동창업자 **안드레이 카파시**가 X(옛 트위터)에 새로운 코딩 방식을 소개했습니다. 코드가 있다는 사실조차 잊고 "분위기(vibe)에 몸을 맡기는" 코딩, 바로 **<Term id="vibe-coding">바이브 코딩</Term>**입니다 ([원문](https://x.com/karpathy/status/1886192184808149383)).

이 말은 그해 콜린스 사전 **올해의 단어(2025)**로 뽑혔습니다 ([Wikipedia](https://en.wikipedia.org/wiki/Vibe_coding)). 의미는 간단합니다. **코드를 모르는 사람도 말로 설명해서 소프트웨어를 만들 수 있게 됐다**는 것입니다.

<Analogy title="행정 업무로 비유하면">
  예전에는 프로그램 하나를 만들려면 기획서 → 예산 → 외주·전산팀 → 수개월이 필요했습니다. 이제는 업무 지시를 하듯 말로 설명하면 몇 분 안에 동작하는 도구가 나옵니다.
</Analogy>

### 그런데 바이브만으로는 사고가 난다

"알아서 해줘"로만 맡기면 문제가 생깁니다. 실제로 있었던 일입니다.

| 시기 | 사건 | 교훈 |
| --- | --- | --- |
| 2025년 5월 | 한 바이브 코딩 플랫폼으로 만든 웹앱 1,645개 중 170개에서 개인정보 노출 취약점 발견 | 만든 뒤 **보안 점검**을 건너뛰었다 |
| 2025년 7월 | 한 AI 코딩 서비스가 "변경 금지" 지시에도 사용자의 운영 데이터베이스를 삭제 | AI에게 **되돌릴 수 없는 권한**을 줬다 |

출처: [Wikipedia — Vibe coding](https://en.wikipedia.org/wiki/Vibe_coding)

만드는 것은 AI가 해도, **무엇을 만들지 정하고 결과를 확인하는 것은 사람의 몫**입니다.

### 에이전틱 엔지니어링

카파시는 2026년 4월 세콰이아 어센트에서 이렇게 정리했습니다. "바이브 코딩은 바닥을 올리고, 에이전틱 엔지니어링은 천장을 올린다" ([요약 기사](https://www.aibuilderclub.com/blog/karpathy-agentic-engineering)).

**<Term id="agentic-engineering">에이전틱 엔지니어링</Term>**은 AI 에이전트가 계획·작성·테스트를 하고, 사람은 **요구사항 정의 → 계획 검토 → 결과 검증**을 맡는 일하는 방식입니다.

| 구분 | 바이브 코딩 | 에이전틱 엔지니어링 |
| --- | --- | --- |
| 태도 | "알아서 해줘" | "이렇게 해줘, 그리고 확인할게" |
| 시작 | 바로 만들기 | 계획 먼저 보기 (플랜 모드) |
| 안전장치 | 없음 | 버전 관리(Git), 검증 기준, 권한 승인 |
| 어울리는 일 | 나만 쓰는 일회용 도구 | 동료가 쓰는 도구, 배포하는 서비스 |

<Callout type="info" title="직원 관점으로 번역하면">
  우리가 이미 잘하는 일입니다. **기획서 쓰기, 업무 지시하기, 결과물 검토하기.** 행정 역량이 곧 개발 역량이 되는 시대입니다. 이 과정의 1~2회차는 바이브 코딩으로 가볍게, 3회차부터는 에이전틱 엔지니어링의 안전장치를 하나씩 더해 갑니다.
</Callout>

### 인스턴트 소프트웨어의 시대

벤처캐피털 a16z의 아니시 아차르야는 2025년 8월 이렇게 썼습니다. 소프트웨어를 만들지 말지는 그동안 **투자 대비 효과**가 결정했지만, 이제는 **상상력**만이 한계라고요 ([Disposable Software](https://a16z.com/disposable-software/)).

<Term id="instant-software">인스턴트 소프트웨어</Term>는 필요할 때 말로 만들어 쓰고, 필요 없으면 지우는 작은 도구입니다. 산학협력단에서는 이런 일들이 후보입니다.

- 과제별 집행 엑셀 50개 취합
- 증빙 파일명 일괄 변경
- 협약서에서 만료일 추출
- 행사 참가자 명찰 생성

모두 "프로그램까지 만들 일은 아니던" 일입니다. 이제는 10분이면 만들고, 다 쓰면 지워도 됩니다.

### 챗봇과 에이전트는 무엇이 다른가

| | 챗봇 (웹 채팅) | 에이전트 (Claude Code) |
| --- | --- | --- |
| 파일 | 내가 올리고, 답을 복사해 내가 저장 | **내 컴퓨터 폴더를 직접 열어 읽고 씀** |
| 실행 | 내가 직접 | 프로그램을 실행하고 결과를 확인 |
| 반복 | 틀리면 내가 다시 질문 | 스스로 확인하고 고침 |
| 사람의 역할 | 손발 | **지시하고 승인하기** |

아래에서 같은 일을 두 방식으로 시켜 보세요.

<Sim name="chat-vs-agent" />

에이전트는 중요한 행동(파일 수정, 명령 실행) 전에 **권한을 묻습니다**. 이 승인 버튼이 우리의 첫 번째 안전장치입니다. 플랜 모드를 켜면 아예 계획만 세우고 멈춥니다.

<Sim name="agent-loop" />

<Callout title="Anthropic 안에서는 이렇게 씁니다">
  Anthropic 법무팀은 담당 변호사 안내 도구를, 마케팅팀은 광고 수백 건을 분석해 새 문구를 만드는 도구를 개발자 없이 만들었습니다. 파일을 옮기고, 바꾸고, 대량으로 분석하는 일이 비개발자에게 가장 쓸모 있는 영역입니다 ([How Anthropic teams use Claude Code](https://claude.com/blog/how-anthropic-teams-use-claude-code)).
</Callout>

### 기획과 개발이 한 사람 안에서

- **예전:** 기획자가 문서로 설명 → 개발자가 해석 → 결과물이 생각과 다름 → 재수정. 번역 손실이 크다
- **지금:** 업무를 가장 잘 아는 사람이 직접 만들고, 쓰면서 바로 고친다. **기획서가 곧 설계도**다

## 시연

강사가 같은 요청을 웹 채팅과 Claude Code에 각각 보내 차이를 보여 줍니다.

<Steps>
<FdStep>
**웹 채팅에** "이 폴더 파일들을 업무별로 정리하는 방법 알려줘" → 방법만 알려 주고, 파일 목록은 사람이 붙여 넣어야 함
</FdStep>
<FdStep>
**Claude Code에** 같은 요청 → 폴더를 직접 열어 파일 32개를 읽고 분류 계획을 표로 제시
</FdStep>
<FdStep>
**계획 승인** → 실제로 폴더가 생기고 파일이 옮겨지는 것을 파일 탐색기에서 함께 확인
</FdStep>
</Steps>

<Trouble>
<Issue q="폴더 접근 권한을 묻는 창이 떠요">처음 폴더를 열 때 정상입니다. 무엇을 하려는지 읽고 허용하세요. 실습 폴더 이외의 폴더(바탕화면 전체 등)는 열지 않는 것이 좋습니다.</Issue>
<Issue q="한글 파일명이 깨져 보여요">압축을 풀 때 깨진 경우입니다. Windows 기본 압축 풀기 대신 반디집 등으로 다시 풀거나, 자료실의 영문 파일명 버전을 사용하세요.</Issue>
<Issue q="로그인이 안 돼요">무료 계정이면 Claude Code를 쓸 수 없습니다. Pro 이상 플랜인지 확인하세요.</Issue>
</Trouble>
